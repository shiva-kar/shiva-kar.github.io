PROJECT 01 · JAVA BACKEND

E-Commerce Backend API

Java Spring Boot Spring Security Spring Data JPA Hibernate PostgreSQL Maven JUnit 5 Mockito Docker Compose Flyway

An e-commerce backend built with Java and Spring Boot, providing REST APIs for product management, shopping carts, orders, and user accounts, with PostgreSQL persistence and secure authentication.

Application Architecture Flow
Client → Spring Security (JWT) → REST Controllers → Service Layer (Locking / Tx) → Repositories (Spring Data JPA) → PostgreSQL

Architecture

  • Layered controller-service-repository architecture with dependency injection
  • DTO-based request and response handling with separation of API models and persistence entities
  • Service-layer business logic with centralized exception handling

REST APIs

  • Product management, category management, shopping carts, order processing, and user account operations
  • Pagination, sorting, filtering, request validation

Authentication & Authorization

  • Spring Security with JWT authentication and password hashing
  • Role-based authorization with protected endpoints

Database Design

  • PostgreSQL with Spring Data JPA and Hibernate
  • Relational entity relationships, database constraints, and Flyway migrations

Transaction Management

The application implements transactional order processing and inventory reservation with locking-based concurrency control to prevent overselling. When multiple users attempt to purchase the same limited inventory simultaneously, the application prevents conflicting reservations and maintains consistent stock levels.

Testing

  • JUnit 5 and Mockito for service-layer testing and integration tests
  • Validation and exception scenarios, transaction and inventory consistency tests

Development Environment

  • Maven build, Docker Compose with PostgreSQL service configuration, Flyway migrations
PROJECT 02 · BACKEND INFRASTRUCTURE

API Rate Limiter & Usage Metering Service

Java Spring Boot Spring Security Redis Maven JUnit 5 Mockito Docker

A Redis-backed API rate-limiting service using the Token Bucket algorithm to enforce configurable per-user and per-API-key request limits, with usage metering and concurrency-safe request handling.

This is not another CRUD application. It is backend infrastructure and algorithmic engineering — focused on algorithms, Redis, atomic operations, concurrency, request control, HTTP behaviour, and usage metering.

Request Flow & Algorithmic Rate Limiting
Client Request → Spring Boot Filter → Token Bucket Engine → Redis (Atomic Lua & TTL) → HTTP 200 / 429 Response

Rate-Limiting Algorithm

  • Token Bucket algorithm with configurable request limits
  • Per-user and per-API-key restrictions with controlled burst handling

Redis Implementation

  • Redis-backed rate-limit state with TTL-based expiration
  • Atomic Lua scripts for concurrent request handling — a rate limiter must not allow simultaneous requests to update shared state incorrectly

HTTP API Behaviour

  • HTTP 429 Too Many Requests with Retry-After headers
  • Rate-limit headers, API key identification, configurable policies
  • Usage metering for per-client tracking

Testing

  • JUnit 5 and Mockito for boundary tests, expiration tests, and concurrent-burst test scenarios
PROJECT 03 · SYSTEMS PROGRAMMING

SXSHELL — Unix-like Shell

C POSIX CMake
View Repository ↗

A modular Unix-like shell implemented in C, with command parsing, process execution, pipelines, and I/O redirection using POSIX system calls.

  • Seven modules (~550 lines) with separation of command parsing and process execution
  • Pipelines and I/O redirection using fork(), execv(), and dup2()
  • Built-in commands, executable lookup, $PATH resolution, and quote/escape parsing

This project demonstrates systems programming fundamentals and general computer science knowledge — process management, file descriptors, and low-level command execution.
